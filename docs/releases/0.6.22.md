# StageMesh 0.6.22

> Superseded by 0.6.23 for real-provider planning output and internal task
> isolation. Upgrade instead of using 0.6.22 for normal queue runs.

StageMesh 0.6.22 prevents useful executed planning from being discarded only
because a provider returned a finding summary slightly beyond the bounded
artifact contract.

## Provider finding normalization

- The challenger prompt now states the maximum finding count and the
  500-character limit for every finding summary.
- Valid string summaries that still exceed the limit are deterministically
  shortened at the provider boundary and carry an explicit
  `[truncated by StageMesh]` marker in the stored planning challenge.
- The strict planning-artifact validator is unchanged. Invalid containers,
  unknown fields, invalid finding kinds, non-string summaries, excessive
  finding counts, and oversized manually supplied artifacts continue to fail
  closed.

## Verification boundary

The release candidate must pass focused planning execution and strict artifact
validation tests, packaging checks, attribution validation, and the
authoritative Linux and Windows hosted suites. It does not start Caventra work
or modify Caventra product or research source.
