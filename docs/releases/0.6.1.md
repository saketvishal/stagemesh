# StageMesh 0.6.1

StageMesh 0.6.1 is a compatible patch release. Publication is established only by the annotated `v0.6.1` tag, its non-prerelease
GitHub release, a successful trusted-publishing workflow, and the resulting immutable PyPI file; these notes alone are not publication.

## Safer first run

- Ordinary `stagemesh init` reports success only when the project has real validation gates, synchronized task sources, and enough
  explicitly authorized available providers for its review policy.
- Incomplete projects receive structured blockers and concrete fixes. The bounded `--allow-incomplete` option creates safe setup files
  for packaging and synthetic harnesses without claiming readiness.
- Repeating initialization is idempotent and preserves existing profile and provider-registry edits.

## Clearer operator interface

- `stagemesh --help` shows the everyday operator commands instead of the complete maintenance surface.
- `stagemesh --help-all` retains a categorized catalog of every compatible command. Existing command names remain callable.
- Installed-versus-source freshness checks use a stable machine-readable command catalog rather than scraping human help text.
- PR-mode refusal now explains that `git pull` cannot remove local-only commits and that StageMesh will not push or reset unreviewed work.

## Windows package reliability

- Bundled skill resources use compact deterministic physical wheel paths while retaining their logical names, upstream provenance, and
  content-integrity checks.
- Package acceptance installs the wheel in a deliberately deep Windows environment and verifies all five bundled skills.
- Pip uninstall removes the active environment's package but deliberately leaves each project's `.stagemesh` configuration, audit
  history, and runtime data intact.

## Publication safety

The release workflow builds from the exact clean tag, rejects a tag/version mismatch, verifies the wheel and a fresh installed runtime,
and publishes through environment-scoped PyPI Trusted Publishing. Installing the release does not start providers, authorize unattended
model use, reconcile an ahead or dirty Git branch, activate a schedule, or delete project-local state. Retain `0.6.0` and project-state
backups for rollback.
