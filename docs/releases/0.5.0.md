# StageMesh 0.5.0

This minor release adds compatible operator capabilities and strengthens
execution control relative to 0.4.0. The published GitHub release and annotated
`v0.5.0` tag are the publication record; these notes alone are not publication.

## Changes

- A dependency-free `stagemesh serve` command exposes a loopback, authenticated,
  read-only activity API and packaged browser dashboard. The dashboard supports
  filtering, sorting, paging, task details and controlled polling. Invalid or
  unauthorized requests pause automatic polling; transient failures remain
  retryable. Strict request parsing and static-asset allowlists limit exposure.
- Exact, case-insensitive GitHub label selection scopes planning, admission and
  automatic recovery. Fresh checks prevent removed labels from admitting work;
  explicit out-of-scope tasks are refused without broadening the selection.
- Durable process-tree ownership and conservative recovery retain unresolved
  provider, validation and researcher executions across parent loss. Stop and
  pause controls avoid claiming cleanup when ownership cannot be established.
- Atomic per-task dispatch and connected-store identity checks prevent stale or
  duplicate admissions. Validation ownership remains visible in operator
  reports and handoffs while inspection is required.
- Provider authorization, bounded driver control, specification/planning gates,
  adverse-review evidence and focused validation receive additional regression
  coverage. Windows Git initialization captures Unicode output as UTF-8.

## Qualification and limits

The integrated feature stack was independently reviewed and tested with native
Windows regressions, real Chromium interactions and an installed wheel. Release
publication additionally requires green checks for the exact release candidate
and actual merged source. The GitHub release manifest links the final commits,
checks and artifact hashes; counts from overlapping suites must not be added.

This is not completion of the Founder Hands-Off acceptance program. Live-provider
delivery, real-world throughput and token savings are not established by fixtures
or CI. The actual nested-tool executor requirement remains blocked on its exact
invocation, provenance and authorized setup. Historical Windows worker failures
and a separate combined research-fixture failure retain UNKNOWN causes despite
current green runs. Non-Chromium and screen-reader qualification is NOT_RUN.
Legacy rows with insufficient ownership metadata remain unqualified; universal
descendant discovery and cleanup are not claimed.

## Install and rollback

Verify the release assets against `SHA256SUMS`. The wheel includes the operator
UI and records its source commit. Publishing this release does not upgrade any
existing runtime, start providers, activate schedules or change client projects.
Installation remains a separately authorized, idle-only operation.

Retain the verified 0.4.0 package and a pre-upgrade state backup. This release
contains persisted-state changes, so a package downgrade alone is not proof of
safe state rollback. Inspect compatibility and use the appropriate preserved
state before any separately authorized rollback; never overwrite a live store.
