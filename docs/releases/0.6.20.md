# StageMesh 0.6.20

StageMesh 0.6.20 completes the human-output compaction started in 0.6.19.
Publication is established only by the annotated `v0.6.20` tag, its
non-prerelease GitHub release, a successful trusted-publishing workflow, and
the resulting immutable PyPI file.

## Compact read-only planning

- Human `run-window --plan` output groups tasks with the same exclusion reason
  into one `left alone` entry.
- Each group displays at most eight task identifiers and an omitted count,
  rather than printing one line per excluded task.
- JSON planning output remains unchanged and retains every task-specific reason
  for automation and audit use.
- Normal executing-window scope summaries and persisted JSON evidence retain
  the 0.6.19 behavior.

## Completed specification dependencies

- Normal and label-scoped run-window refreshes can clear an obsolete
  specification dependency without requiring a separate `init` or queue
  reconciliation command.
- Closure alone never satisfies a dependency. The implementation and
  specification issues must bind to one another, both must name the same exact
  40-character approved commit, the specification must declare `DONE` and be
  closed, and Git must prove the commit is on the local integration branch.
- A successful reconciliation is retained in source state and records a
  `task.dependency_satisfied` audit event with the task, prerequisite, evidence
  kind, and immutable commit.
- Missing, unapproved, mismatched, unmerged, or locally unavailable pins remain
  blocked. Partial source scans do not remove other registered prerequisites.

## Verification boundary

The release candidate must pass focused human and JSON plan-output tests,
source/dependency and run-window regressions, packaging checks, attribution,
and the authoritative Linux and Windows hosted suites. It does not start
Caventra work or modify Caventra product or research source. Dependency
eligibility changes only when the complete fail-closed evidence above is
present.
