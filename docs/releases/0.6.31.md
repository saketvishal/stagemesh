# StageMesh 0.6.31

StageMesh 0.6.31 fixes isolated validation after Caventra task 138 produced a
real candidate but both npm gates failed because the temporary checkout did not
contain the project's installed `vitest` executable.

## Isolated dependency preparation

- Candidate validation now discovers project-local `.venv` and `node_modules`
  directories next to tracked dependency manifests when no explicit mapping is
  configured.
- The existing isolation rules still make a private candidate copy and require
  dependency declarations to match the candidate exactly. npm workspace links
  are rewritten to the corresponding path in the candidate checkout; links
  outside the project or into runtime metadata remain rejected.
- `.stagemesh/validation-environments.json` remains the explicit override for
  non-conventional layouts. No package is downloaded or installed implicitly.

## Correct recovery routing

- Canonical nested-shell failures such as `'vitest' is not recognized` and
  `command not found` are classified as unavailable validation tooling, not as
  implementation defects.
- StageMesh no longer spends a coding-agent attempt asking for source edits that
  cannot install a missing gate executable.
- A normal run can reclassify an older OPEN/IMPLEMENT remediation produced by
  the former behavior, revalidate the same durable candidate once, close the
  superseded environment findings after a pass, and retain the audit history.

## Regression evidence

Synthetic tests cover automatic Node dependency preparation without a manual
StageMesh file, exact nested-shell missing-tool diagnosis, preservation of
ambiguous code failures, existing blocked-gate recovery, and upgrade recovery
from the legacy misrouted task state.

Focused tests, package metadata checks, attribution validation, hosted Linux and
Windows regressions, protected-main review, and public PyPI verification remain
required before publication.
