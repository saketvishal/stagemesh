# StageMesh 0.6.17

StageMesh 0.6.17 is an Antigravity setup and capability-isolation patch.
Publication is established only by the annotated `v0.6.17` tag, its
non-prerelease GitHub release, a successful trusted-publishing workflow, and the
resulting immutable PyPI file; these notes alone are not publication.

> **Known limitation:** later Windows testing with Antigravity CLI 1.5.10
> showed that the generated least-privilege settings path is not yet proven for
> unattended implementation and review. Keep Agy inactive where that live
> acceptance has not passed. The correction is intentionally deferred from the
> logging-only 0.6.18 release.

## Automatic safe setup

- `stagemesh init` creates a project-local Agy settings file when it discovers
  the exact bundled adapter command. The settings enable the terminal sandbox,
  keep non-workspace access disabled, block browser, web and MCP tools, protect
  StageMesh and Git control paths, and deny Git history or delivery commands.
- Existing customized commands and settings remain operator-owned and are not
  overwritten. Setup performs no provider or model call.
- Previous exact StageMesh-generated Agy defaults migrate through the same
  bounded configuration on the next initialization.

## Verified skill attachment boundary

- Agy receives read-only access to StageMesh's verified bundled skill directory
  through an ephemeral derived settings file for the provider process. Writes
  to that directory remain denied, the project settings file is unchanged, and
  the temporary file is removed after implementation or review.
- Explicit Windows `.cmd` and `.bat` launchers use Antigravity's documented
  JSON stream input instead of placing the multi-line task prompt on the Windows
  command line. This avoids command-line truncation and shell interpretation;
  executable launchers continue to use ordinary single-prompt print mode.
- The change keeps full `SKILL.md` bodies off the Windows command line and does
  not enable the dangerous global permission bypass, browser control, network
  fetches or arbitrary host-file access.

## Verification boundary

Focused provider-command and initialization tests cover path and inline settings,
fail-closed invalid settings, Windows launcher input, interrupted-launch cleanup,
managed-path repair, idempotent setup, preservation of custom settings, and zero
provider calls during initialization. The result parser also rejects non-success
top-level and stream statuses before considering structured output, preventing a
stale payload from being treated as a passing implementation or review result.

The exact release-candidate head `93dcae441212ad2aad9e857c6823d5f72e3ff248`
passed the following pre-merge evidence:

- 99 focused provider-event tests and 227 broader provider/readiness tests on
  Windows, plus clean Ruff and `git diff --check` results;
- a bounded synthetic Agy implementation-and-review canary with status `PASS`,
  candidate file verification, and both implementation and review readiness;
- two tool-free, source-only independent Agy review segments covering result
  parsing and least-privilege settings/launcher behavior, each returning `PASS`
  with no P0-P3 findings; and
- StageMesh CI run 1512, where attribution, Linux authoritative regression and
  Windows authoritative platform regression all passed.

The canary proves the bounded synthetic provider path, not general Caventra
development correctness. Publication still requires the annotated `v0.6.17`
tag on the verified merged commit, a non-prerelease GitHub release, successful
trusted publishing, and a fresh public-index installation. No Caventra product
or research source is changed by this release.
