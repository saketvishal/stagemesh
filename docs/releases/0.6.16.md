# StageMesh 0.6.16

StageMesh 0.6.16 is a governed-readiness and operator-safety patch. Publication
is established only by the annotated `v0.6.16` tag, its non-prerelease GitHub
release, a successful trusted-publishing workflow, and the resulting immutable
PyPI file; these notes alone are not publication.

## Governed project setup

- `stagemesh init --governance-profile governed-sdd` atomically enables approved
  planning specifications, a distinct planning challenger, independent review,
  and PR-only delivery.
- Setup selects only installed and explicitly authorized provider adapters for
  planner and challenger roles. It never invents an accountable authority or
  approver identity; those values remain explicit operator inputs.
- Configuration validation rejects attempts to weaken any governed profile gate
  or assign an unauthorized planning provider. Legacy projects remain opt-in.
- A bounded synthetic acceptance test proves governed initialization refuses at
  planning execution before implementation and records zero provider calls.

## Truthful readiness and Windows output

- `stagemesh doctor` reports configured governance identities and roles, failed
  GitHub access, authorized providers whose command or unattended permission is
  unavailable, and non-code source tasks outside the coding queue.
- No-edit and operations-gate source tasks are not counted as live coding work or
  repeatedly offered to coding providers.
- The Windows console entry point uses UTF-8-safe output, so valid Unicode task
  titles do not crash status or queue commands under a legacy code page.
- A detached Windows npm `codex.exe` is redirected only within a recognized npm
  Codex installation to that package's complete binary and code-mode host. A
  custom or unrelated executable is never substituted.

## Verification boundary

Focused configuration, initialization, planning-gate, readiness, queue-output,
and controlled-delivery tests cover this patch on synthetic repositories. The
release candidate still requires independent exact-candidate review, the normal
Linux and Windows CI gates, a successful trusted-publishing run, and a clean
installation from the public index before 0.6.16 is considered published or
ready for a client upgrade. No Caventra product or research source is changed by
this release.
