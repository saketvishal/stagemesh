# StageMesh 0.6.23

StageMesh 0.6.23 hardens the boundary between real coding-agent responses,
internal acceptance bookkeeping, and schedulable project work.

## Provider planning responses

- Planner and challenger roles accept exactly one valid JSON object when a
  headless provider wraps it in a Markdown fence or brief explanatory text.
- Multiple objects, malformed structural text, arrays, scalars, unknown fields,
  and invalid planning artifacts still fail closed.
- Existing output-size, read-only checkout, authorization, provider-independence,
  and receipt checks are unchanged.

## Internal task isolation

- Deterministic provider acceptance closes its synthetic task record after the
  check, including on exceptional exits.
- The scheduler independently refuses internal provider-acceptance records.
- A schema migration retires a leaked open record created by an older release,
  so an upgraded project does not need manual database repair.

## Verification boundary

The release candidate must pass focused real-Git planning and provider
acceptance tests, adjacent planning/queue/recovery suites, packaging checks,
attribution validation, and the authoritative Linux and Windows hosted suites.
It does not start Caventra work or modify Caventra product or research source.
