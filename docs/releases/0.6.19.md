# StageMesh 0.6.19

StageMesh 0.6.19 is a corrective Antigravity capability-isolation and CI
efficiency patch. Publication is established only by the annotated `v0.6.19`
tag, its non-prerelease GitHub release, a successful trusted-publishing
workflow, and the resulting immutable PyPI file; these notes alone are not
publication.

## Accepted headless settings

- New project settings omit the editor-only `$schema` annotation, which
  Antigravity CLI 1.5.10 rejects before launching a provider task.
- Initialization migrates only the exact StageMesh-generated 0.6.17 settings
  object. Customized settings remain operator-owned and unchanged.
- Generated settings grant no terminal command permission. StageMesh owns Git
  and validation instead of granting Agy broad terminal access.

## Exact read-only bundled-skill access

- StageMesh derives deterministic exact `read_file` permissions for every
  regular, non-symlink file in the verified bundled-skill resource tree. Each
  permission has a matching `write_file` deny.
- Resolved resource paths must remain under the verified resource root.
  Missing resources, invalid settings, symlinks, and escaping paths fail closed
  before provider launch.
- Permissions are process-local and ephemeral. StageMesh does not grant a
  `read_file(*)` wildcard, browser, web, MCP, dangerous-bypass, or arbitrary
  host-file access.

## Headless implementation and review

- Agy receives prompts through JSON streaming rather than Windows command-line
  arguments. Prompts require native file reads and forbid terminal, Git,
  browser, web, and MCP use.
- StageMesh owns repository and validation operations. For review it supplies a
  bounded exact candidate patch; an oversized patch fails closed instead of
  expanding provider access.
- Existing customized provider commands remain operator-owned.

## One authoritative hosted validation path

- Pull requests and merge-queue candidates retain hosted validation. Scheduled
  and manual complete regressions also remain available.
- The automatic `push` trigger on `main` is removed, so merging an already
  validated pull request does not start the same hosted workflow again.

## Compact human output

- A selected label scope is summarized once in the final human report with
  matching, eligible, blocked, and excluded counts. The command no longer dumps
  the complete exclusion object before the run and again in the final report.
- Large same-reason `left alone` groups show a bounded task sample and the
  number omitted. Complete per-task scope and exclusion evidence remains in the
  persisted JSON report and machine-readable output.

## Verification boundary

The release candidate must pass focused permission, prompt, provider-event,
provider-initialization, scope-output, CI-policy, packaging, and live acceptance tests. Its
live Antigravity canary must start from candidate-generated settings, read a
bundled skill through exact-file permission, implement a bounded synthetic
change, and complete review without browser or terminal access. Hosted Linux,
Windows, and attribution checks must pass on the exact pull-request head.

The canary proves only this bounded provider and permission path. It does not
prove general Caventra development correctness, change Caventra product or
research source, or override any project's autonomous-dispatch policy.
