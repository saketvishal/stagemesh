# StageMesh 0.6.2

StageMesh 0.6.2 is a compatible patch release. Publication is established only by the annotated `v0.6.2` tag, its non-prerelease
GitHub release, a successful trusted-publishing workflow, and the resulting immutable PyPI file; these notes alone are not publication.

## Authoritative initialization

- `stagemesh init` checks the same static checkout and origin relationship required by the default PR-mode run window.
- A local integration branch that is ahead of or diverged from origin is reported during initialization. StageMesh preserves the work
  and provides the feature-branch/PR recovery direction instead of resetting or publishing it automatically.
- A missing local or remote integration ref fails closed instead of being presented as a usable PR-mode repository.
- Incomplete initialization states explicitly say that `run-window` will refuse; only a ready initialization exits successfully.

## Consistent provider authorization

- Run-window preflight now evaluates provider adapters in unattended mode, matching the dispatch boundary.
- Installed or authenticated CLIs that lack project-local `authorization.unattended_providers` consent are no longer reported as an
  available implementation/review pool.
- Provider authorization remains an explicit per-project opt-in. Initialization and preflight make no model calls.

## Verification

The release candidate includes synthetic tests for an origin-aligned ready repository, a local-only commit refusal, a missing-origin
refusal, and unauthorized-versus-authorized provider pools. Existing initialization, run-window, provider-pool, and authorization
suites remain required before publication.
