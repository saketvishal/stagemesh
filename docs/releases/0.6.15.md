# StageMesh 0.6.15

StageMesh 0.6.15 is a task-admission and provider-safety patch. Publication is established only by the annotated `v0.6.15` tag, its non-prerelease GitHub release, a successful trusted-publishing workflow, and the resulting immutable PyPI file; these notes alone are not publication.

## No-edit GitHub contracts

- An issue whose `Allowed files` section says `No repository file edits` is excluded before auto-planning or provider selection whether the section uses a colon, bold text, or a Markdown heading.
- The explicit no-edit phrase remains authoritative when the same line continues with an explanation of permitted metadata actions.
- Scheduler-time reconciliation applies the rule to cached tasks from older releases, so rerunning an existing project does not require rewriting its issue or ledger.

## Grok headless execution

- Grok's built-in tool filter now uses the provider's documented `Read`, `Grep`, `Edit`, and `Bash` tool names instead of invalid compatibility names that caused the filter to be ignored.
- Unattended Grok runs use `dontAsk`, the provider's documented headless permission mode. Only StageMesh's explicit allow rules can execute; unmatched actions fail closed instead of trying to prompt an unattended process.
- `stagemesh init` narrowly migrates the exact 0.6.14 Grok default while preserving customized commands.
- Structured `REVIEW_INCOMPLETE` progress records no longer invalidate one later terminal review verdict; multiple terminal verdicts still fail closed as ambiguous.
- Live progress stops presenting the internal deterministic fallback label as the active reviewer and switches heartbeats to the provider StageMesh actually selected.
- A structured AGY `denied_actions` result is recorded as a permission failure instead of a malformed review.

## Verification boundary

Synthetic source-discovery, cached-ledger reconciliation, provider-command, exact-default migration, review-protocol, progress-reporting, and runtime-hardening tests cover this patch. The real cached Accordmore issue #3 body was parsed read-only and produced `source task permits no repository file edits`. A separate read-only inspection of a 0.6.13 CaventraQ run confirmed Grok progress records followed by single terminal PASS or finding verdicts, plus structured AGY permission denials. No provider was invoked while preparing the correction.
