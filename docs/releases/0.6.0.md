# StageMesh 0.6.0

StageMesh 0.6.0 is the first PyPI release candidate. Publication is established only by the annotated `v0.6.0` tag, its non-prerelease
GitHub release, a successful trusted-publishing workflow, and the resulting immutable PyPI files; these notes alone are not publication.

## New-project experience

- The verified public installation path is `python -m pip install stagemesh`.
- The installed console command is exercised in a fresh environment and must initialize an empty project before publication.
- Fresh GitHub projects detect their repository and task source. With explicit Issues write authorization, completely unlabeled issues
  are classified as `stagemesh:ready` when deterministically plannable or `stagemesh:needs-triage` when more information is required.
- Initialization preserves existing labels and explicit source/provider policy, records classification evidence, and makes zero provider
  calls. Starting coding, publishing a PR, and merging remain separately authorized operations.

## Publication safety

- The release workflow runs only when a non-prerelease GitHub release is explicitly published.
- The exact tag must equal the stable version embedded in the wheel.
- The wheel must carry a clean source commit, safe unique paths, the CLI entry point, supported Python metadata, and the README.
- PyPI authentication uses environment-scoped GitHub OIDC Trusted Publishing; no long-lived upload token is stored.
- Existing PyPI files are never replaced or skipped. A failed or corrected release receives a new version.

Retain the verified 0.5.0 GitHub release wheel and project-state backups for rollback. Installing or publishing 0.6.0 does not update an
existing runtime, start providers, activate schedules, or prove that a persisted database can be safely downgraded.
