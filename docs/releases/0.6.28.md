# StageMesh 0.6.28

StageMesh 0.6.28 closes a real-provider planning protocol gap found while
resuming Caventra task 138. The planner returned prose and external references
where StageMesh required project-relative specification paths.

## Bounded provider correction

- Planner prompts now state that `affected_paths` and `spec_refs` contain paths,
  not prose, URLs, issue references, or pull-request references.
- Provider-authored `spec_refs` must resolve to existing, non-empty files inside
  the exact project checkout. An empty list remains valid when no local
  specification applies.
- A malformed planner response receives exactly one protocol-only correction
  containing the validation error and the original bounded request.
- The correction is recorded as an audit event and a distinct execution. If the
  second response is invalid, planning stops without publishing the response or
  starting another provider loop.

## Regression evidence

- Synthetic tests cover malformed references during automatic plan revision,
  successful correction, persistent invalid output, exact two-attempt bounding,
  preserved planning artifacts, and durable audit evidence.
- The installed-wheel development journey now deliberately produces malformed
  planner references during both initial planning and revision. Release
  qualification must observe and audit both bounded corrections before it can
  report all 18 steps complete.

Focused tests, the exact repository quality gate, the clean installed-wheel
journey, hosted Linux and Windows regressions, attribution validation, and
protected-main review remain required before publication.
