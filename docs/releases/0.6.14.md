# StageMesh 0.6.14

StageMesh 0.6.14 is a runtime-safety patch. Publication is established only by the annotated `v0.6.14` tag, its non-prerelease GitHub release, a successful trusted-publishing workflow, and the resulting immutable PyPI file; these notes alone are not publication.

## Contract-aware GitHub admission

- Explicit program and tracking markers cannot be executed merely because an issue still has `stagemesh:ready`.
- Operations gates, source-declared blocked work, and tasks that permit no repository edits stay out of coding-provider routes until StageMesh has a compatible non-code adapter.
- Scheduler-time reconciliation applies the same rule to durable task rows created by older releases without erasing their audit history.
- `PR #N` and `pull request #N` references are no longer misread as issue dependencies.
- Initialization now says that its classification totals cover only previously-unlabeled issues changed in that pass.

## Provider and interruption safety

- Generic provider prose containing “not found” is no longer misclassified as a missing provider executable.
- AGY is eligible for unattended coding only when its command includes an explicit `--settings` file; StageMesh does not enable AGY's dangerous permission bypass.
- Provider health explains the missing AGY unattended permission setup before a real task is attempted.
- Ctrl+C requests project-scoped provider termination, waits for bounded cleanup, writes the finished window journal, avoids a post-interrupt GitHub lookup, and returns a normal stopped report instead of a traceback.

## Verification boundary

Synthetic admission, dependency, provider-capacity, failure-classification, scheduler-reconciliation, interruption, and initialization tests cover this patch. No live provider, browser, or Caventra task was invoked during the focused acceptance run.
