# StageMesh 0.6.21

> Superseded by 0.6.22 for executed planning. In 0.6.21 an otherwise valid
> provider challenge could be refused when an individual finding summary
> exceeded the 500-character artifact boundary.

StageMesh 0.6.21 closes a fail-closed gap found during the final Caventra
acceptance check for 0.6.20. Publication is established only by the annotated
`v0.6.21` tag, its non-prerelease GitHub release, a successful trusted-publishing
workflow, and the resulting immutable PyPI file.

## Governing specification hold

- An open implementation issue that names a governing specification remains
  dependent on that specification until completed-spec evidence is verified.
- This hold is reconstructed during normal and label-scoped refresh even when
  an earlier manual reconciliation removed the scheduler edge or the issue says
  `Depends on: none`.
- The hold clears only when the implementation and specification cross-bind,
  the specification is closed and declares `DONE`, both carry the same exact
  40-character approved pin, and Git proves that pin is on the integration
  branch.
- Missing, mismatched, unapproved, unmerged, off-branch, or locally unavailable
  pins remain blocked. A merely closed issue is still insufficient.

## Verification boundary

The release candidate must pass the focused source reconciliation tests, the
full run-window suite, packaging checks, attribution, and the authoritative
Linux and Windows hosted suites. It does not update Caventra's local branch,
start Caventra work, or modify Caventra product or research source.
