# StageMesh 0.6.48

StageMesh 0.6.48 completes the persisted-state upgrade introduced in 0.6.47.
An existing task that spent its generic automatic recovery budget before a
newer verified browser capture was recorded may now enter the exact-candidate
independent re-review once, without rerunning implementation.

## What changed

- A verified capture newer than every open browser or internal-acceptance
  finding authorizes one evidence-specific migration even when all three older
  generic recovery attempts were already spent.
- The migration preserves the candidate, review stage, findings, capture, and
  audit history. It does not create a misleading fourth generic retry.
- The same candidate and capture cannot consume the migration twice.
- After migration, the receipt-bound re-review rules from 0.6.47 still apply:
  the reviewer must bind the exact capture ID and PNG hashes before a PASS or
  FAIL_WITH_FINDINGS can become terminal.

## Safety and compatibility

- Tasks without newer verified browser evidence remain blocked.
- Unrelated findings and external dependencies do not receive this migration.
- A repeated block with the same capture remains blocked, preventing another
  recovery loop.
- Provider selection and independent-review policy are unchanged.

## Acceptance coverage

The persisted-state regression records three spent legacy recovery attempts,
the external-evidence block, and the later verified exact-candidate capture. It
proves one migration reaches independent review, closes only attributable stale
findings after an exact receipt, and advances without implementation. The same
test proves that reusing the capture cannot start a second migration.
