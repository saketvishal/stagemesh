# StageMesh 0.6.29

StageMesh 0.6.29 closes the remaining planning-role protocol gap exposed by a
real Caventra task. Version 0.6.28 could correct malformed planner output, but a
fresh independent challenger could still stop planning after returning finding
categories outside StageMesh's bounded schema.

## Shared planning-role correction

- Planner, automatic planner revision, and challenger executions now use the
  same bounded correction boundary.
- Challenger prompts name every accepted verdict and finding kind explicitly.
- A structurally invalid response receives exactly one correction containing
  the validation error, exact schema, and original bounded request.
- Every correction is a separate execution and durable audit event identifying
  the planning role. A second invalid response stops without publishing an
  artifact or starting another retry.
- StageMesh does not silently reinterpret unsupported finding categories.

## Regression evidence

- Synthetic tests cover challenger recovery from multiple unsupported finding
  kinds and persistent invalid output with an exact two-attempt ceiling.
- Existing planner correction and fail-closed tests remain in the same suite.
- The installed-wheel development journey now deliberately violates both the
  planner and challenger protocols during initial planning and automatic
  revision. Release qualification requires all four bounded corrections to be
  recorded before it can report all 18 steps complete.

Focused tests, the exact repository quality gate, the clean installed-wheel
journey, hosted Linux and Windows regressions, attribution validation, and
protected-main review remain required before publication.
