# StageMesh 0.6.10

StageMesh 0.6.10 is a compatible patch release. Publication is established only by the annotated `v0.6.10` tag, its non-prerelease GitHub release, a successful trusted-publishing workflow, and the resulting immutable PyPI file; these notes alone are not publication.

## Headless provider isolation

- Provider subprocesses no longer inherit live Codex Desktop or browser-access bridge variables from the process that started StageMesh.
- Disposable review checkouts therefore remain internal working directories instead of surfacing as `file:///` browser tabs.
- Provider authentication and persistent configuration remain available; the filter removes only interactive desktop/session bindings.
- The protection applies centrally to implementation, planning, remediation, and review provider launches.

## Verification

Synthetic acceptance proves that desktop/browser bridge variables and external editor launchers are removed while provider credentials, persistent configuration, the executable path, StageMesh process marking, and repository-owner Git identity remain intact.

## Provider setup clarity

- Existing projects now receive the same one-step `stagemesh init` authorization choice for every installed but inactive provider as new projects.
- Run-window and doctor reports distinguish an inactive provider from an active provider whose first real execution has not yet been tried; internal phrases such as `live check missing` are no longer shown as operator guidance.
- The required `Attribution policy` check is now a dedicated CI job shared by Linux and Windows, matching the protected-branch rule without running the same check twice.
