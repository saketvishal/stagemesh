# StageMesh 0.6.44

StageMesh 0.6.44 prevents a Windows browser's minimum window size from creating
false responsive-review evidence.

## Verified CSS viewport

- Browser capture now uses the loopback Chrome DevTools Protocol to apply the
  requested device metrics before navigation.
- StageMesh measures `window.innerWidth` and `window.innerHeight` before taking
  the screenshot and refuses the capture if they differ from the request.
- The evidence manifest records the requested viewport, measured CSS viewport,
  device scale factor, PNG dimensions, and SHA-256 digest.
- The browser remains headless and isolated, and StageMesh closes the root
  browser process through its debugger before removing the disposable profile.

## Existing evidence

- Captures that lack measured CSS viewport proof no longer authorize PASS or
  FAIL decisions.
- A persisted FAIL from such a capture resolves only its visual finding, clears
  its exact remediation attempt, preserves the candidate, and returns the task
  to REVIEW for a trustworthy recapture. It cannot dispatch another
  implementation provider.

## Evidence

Synthetic tests cover command isolation, debugger ordering, exact CSS viewport
measurement, mismatch refusal, manifest integrity, and idempotent legacy
failure retirement. A real hidden Edge acceptance capture measured and produced
an exact 360x800 viewport and left no browser process or disposable profile.
A copied production-shaped ledger moved from OPEN/IMPLEMENT to BLOCKED/REVIEW,
resolved only the unverified cropped-screenshot finding, cleared its specific
remediation, preserved the candidate, and retained a separate acceptance-record
finding. No live project database or source tree was modified.
