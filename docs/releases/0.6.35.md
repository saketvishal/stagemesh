# StageMesh 0.6.35

StageMesh 0.6.35 preserves an already approved planning decision across safe
runtime upgrades and makes planning-admission reporting truthful.

## Approved plans remain usable

- An accountable approval remains valid when it still binds the exact current
  plan, independent challenge, task contract, baseline, approval authority, and
  durable successful planning identities.
- A later change to the configured planner command does not invalidate that
  historical evidence because no planner or challenger is launched at task
  pickup.
- Unapproved plans, manually supplied artifacts, changed plans, stale
  contracts, stale baselines, invalid receipts, and missing role identities
  continue to fail closed.

## Run-window reports actionable outcomes

- A window that delivers no task because every attempted task was refused now
  returns `STOPPED` with a nonzero exit code instead of `OK`.
- If a GitHub issue closes during the window, StageMesh does not leave a stale
  instruction to approve or resume that issue.
- Open tasks retain their task-specific next action; source closure does not
  erase guidance for independent work that is still actionable.

## Regression evidence

Tests cover approved and unapproved provider-command drift, post-approval plan
mutation, all-refused window status, exact approval guidance, and source closure
during a run. Package metadata, attribution validation, hosted Linux and
Windows regression, protected-main review, and public PyPI verification remain
required before publication.
