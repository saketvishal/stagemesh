# StageMesh 0.6.27

StageMesh 0.6.27 replaces release-by-static-assertion with one executable,
current-candidate development journey. It also closes the planning loop for
actionable independent-review findings without bypassing human decisions.

## Executable release qualification

- CI, local acceptance, and release readiness consume one authoritative gate
  manifest.
- PyPI publishing executes the installed-wheel development journey on the
  exact release tag before it can build or publish an artifact.
- A disposable installed-wheel journey exercises initialization, task
  discovery, planning, one revision, fresh challenge, accountable approval,
  interrupted implementation, ordinary resume, validation, two independent
  review roles, local integration, restart, and non-redispatch.
- The journey writes a candidate-bound audit receipt. Missing, failed,
  partial, dirty-tree, or stale-candidate evidence remains `INCOMPLETE`.
- Older static completion rows now say `COVERED_NOT_EXECUTED`; naming a test
  file is no longer reported as proof that the current candidate ran it.
- Redundant standalone installation gates are removed from the release
  manifest because the development journey installs and initializes the
  candidate wheel itself.

## Bounded planning correction

- A `revise` challenge with concrete findings and no human decision receives
  exactly one serialized planner revision followed by a fresh independent
  challenge.
- The prior spec and challenge are archived with durable intent, completion,
  and abort events. Interrupted artifact transitions restore the authoritative
  pair.
- Persistent findings stop with the saved challenge path; StageMesh does not
  suggest an identical rerun or loop providers.
- `needs-human-decision` remains an operator boundary and is never rewritten
  or approved automatically.
- Newly planned tasks bind their baseline and explicit contract before the
  approval boundary, so the approval command cannot fail because identity was
  deferred until implementation.

Focused planning and qualification tests, the clean installed-wheel journey,
hosted Linux/Windows checks, attribution validation, and protected-main review
remain required before publication.
