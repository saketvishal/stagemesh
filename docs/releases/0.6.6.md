# StageMesh 0.6.6

StageMesh 0.6.6 is a compatible patch release. Publication is established only by the annotated `v0.6.6` tag, its non-prerelease
GitHub release, a successful trusted-publishing workflow, and the resulting immutable PyPI file; these notes alone are not publication.

## Zero-friction GitHub admission

- Interactive `stagemesh init` uses the current authenticated GitHub CLI when no explicit StageMesh token is configured. The token is
  captured in memory for the command, never printed, and never written to project configuration or audit data.
- Non-interactive initialization can opt into the same behavior with `--use-gh-auth`; `STAGEMESH_GITHUB_TOKEN` remains supported.
- Classification now considers open issues that lack a StageMesh admission label even when they already carry ordinary team labels.
- Existing labels are preserved. Issues already marked ready, needs-triage, blocked, deferred, remediating, or as objective roots are not
  relabeled by this bootstrap path.
- Safely plannable issues receive `stagemesh:ready`; issues lacking deterministic scope or validation receive
  `stagemesh:needs-triage`. Successful changes are resynced before initialization returns, making runnable work immediately visible.
- The process remains provider-free and fail closed: unavailable credentials or rejected writes cannot make an issue runnable.

## Verification

The candidate includes synthetic acceptance for GitHub CLI token capture, token non-persistence, preservation of ordinary team labels,
bounded StageMesh-only label writes, post-write resynchronization, missing-authorization refusal, scripted compatibility, initialization,
and GitHub task-source regressions.
