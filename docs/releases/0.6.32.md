# StageMesh 0.6.32

StageMesh 0.6.32 fixes the unattended Codex review failure observed after
Caventra task 138 validated successfully. The reviewer could start, but its
execution policy rejected read-only `git status` and `git diff` commands before
they ran because no interactive operator was available to approve them.

## Bounded unattended Codex execution

- StageMesh now launches Codex with its supported `--approve-for-me` mode. Codex
  evaluates tool requests automatically and retains its read-only or
  workspace-write isolation instead of bypassing the sandbox.
- An explicit legacy `--sandbox` option is removed because Codex rejects that
  option when `--approve-for-me` is active.
- Existing project configurations are corrected at invocation time. Exact old
  StageMesh-generated defaults are also migrated by `stagemesh init`; custom
  provider commands remain otherwise untouched.
- `--dangerously-bypass-approvals-and-sandbox` remains prohibited. User account
  configuration remains excluded and provider sessions remain ephemeral.

## Regression evidence

Synthetic tests cover the long and short legacy sandbox spellings, including
`--sandbox=value` and `-s=value`, and prove that the final command contains one
bounded unattended approval mode without a conflicting fixed sandbox. A live
Codex 0.166.0 check independently executed both `git status --short` and
`git diff --stat` without editing the workspace.

Focused tests, package metadata checks, attribution validation, hosted Linux and
Windows regressions, protected-main review, and public PyPI verification remain
required before publication.
