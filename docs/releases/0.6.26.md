# StageMesh 0.6.26

StageMesh 0.6.26 provides a bounded recovery path for a non-accepting planning
challenge created before contract-aware review shipped in 0.6.25. It does not
turn human decisions into automatic approvals or permit repeated reviewer rolls.

## Audited legacy challenge migration

- `stagemesh refresh-planning-challenge --task <id> --reason "<what changed>"`
  is an explicit operator action. It preserves the exact old challenge in
  project-local history and records intent, completion, digest, reason, and
  review-protocol evidence in the audit trail.
- Eligibility uses the verified challenger execution receipt and the exact
  contract-aware merge cutover. A current-protocol challenge with unchanged
  frozen planning inputs is refused.
- Accepted challenges, approval artifacts, durable approval receipts, active
  claims, active executions, unverified challenger receipts, and unsafe history
  paths all fail closed.

## Interruption and concurrency safety

- Refresh uses the same per-task native lock as stage dispatch.
- Interrupted intent is reconciled before planning or a repeated refresh:
  preserved current artifacts are marked aborted, while an already archived
  exact artifact is marked completed.
- Archive bytes are rehashed after the atomic move. Symlink and junction escape
  paths are refused.
- New challenger receipts record the review-protocol version, so a genuine
  current decision cannot be re-run until its frozen planning inputs change.

Focused tests cover legacy/current cutover behavior, accepted and approved
artifacts, durable receipts, claims, executions, provider-process refusal,
concurrent dispatch, audit failures, interrupted retries, archive integrity,
and operator guidance. Hosted Linux, Windows, attribution, packaging, and
protected-main checks remain required before release.
