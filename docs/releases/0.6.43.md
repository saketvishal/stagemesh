# StageMesh 0.6.43

StageMesh 0.6.43 repairs the provider handoff after an accountable headless
browser review records FAIL.

## Exact remediation context

- A visual FAIL now creates the same typed, audit-bound REVIEW remediation used
  by other adverse review findings.
- The next implementation provider receives the exact candidate SHA and the
  approver's recorded visual finding in its remediation prompt.
- Repeated dispatch does not create another remediation while the same
  candidate's REVIEW remediation remains active.

## Existing 0.6.42 projects

- Before implementation dispatch, StageMesh detects a candidate-bound browser
  FAIL that has an open visual finding but no remediation ledger entry.
- It reconstructs the missing typed retry and remediation context, so users do
  not need to repeat the browser decision or edit project state by hand.

## Evidence

Synthetic regressions prove both the new decision path and recovery of the
legacy persisted state. A read-only copy of Caventra task 138's production
StageMesh database was exercised with the fix: the missing remediation was
reconstructed, its retry was audit-bound, and the exact 360-pixel clipping
finding appeared in the provider prompt. The live Caventra task and source tree
were not modified during this qualification.
