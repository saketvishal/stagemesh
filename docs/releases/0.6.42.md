# StageMesh 0.6.42

StageMesh 0.6.42 turns a retained candidate's missing responsive-browser
evidence into a bounded, no-window operator workflow instead of another
implementation retry.

## Headless exact-candidate capture

- `stagemesh evidence capture-browser` starts an explicit project server in the
  retained candidate worktree and captures named loopback routes at declared
  viewports with an installed Edge, Chrome, or Chromium executable.
- The browser always runs headlessly with an isolated disposable profile.
  StageMesh does not open a desktop window, attach a browser-control bridge,
  install a browser, or add a project dependency.
- PNG dimensions, SHA-256 hashes, paths, candidate identity, and a redacted
  server command are written to a project-local manifest and audit event.

## Accountable decision and recovery

- `stagemesh evidence decide-browser` records PASS or FAIL under the project's
  configured approval authority. Provider subprocesses cannot record either
  the capture or the human decision.
- PASS unlocks `retry-task` only for the same candidate and latest capture, and
  only while every artifact remains present, project-local, dimensionally
  correct, and hash-identical.
- FAIL creates exact-candidate REVIEW evidence and an actionable finding, then
  returns the task to IMPLEMENT without discarding its history.
- `diagnose` and independent review receive the bounded browser-evidence
  context; screenshots remain untrusted evidence data rather than instructions.

## Evidence

Synthetic regression covers hostile capture inputs, strict headless flags,
provider self-approval refusal, candidate-bound PASS, FAIL remediation routing,
retry refusal before acceptance, and artifact-tamper invalidation. A live
Windows qualification captured four screenshots from a retained Caventra task
candidate without displaying a browser window and exposed a real 360-pixel
horizontal-overflow defect. That product finding remains unaccepted until the
configured human authority records its visual decision.
