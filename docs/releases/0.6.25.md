# StageMesh 0.6.25

StageMesh 0.6.25 corrects accountable planning feedback before implementation.
It does not weaken operator approval or replace unresolved design decisions with
an automatic model verdict.

## Contract-aware independent challenge

- The independent challenger receives the bounded task contract as well as the
  frozen planning spec, so it can check the plan against the actual objective,
  scope, prerequisites, and acceptance evidence.
- Both inputs remain explicitly untrusted data. Contract prose cannot grant
  operator approval, and the separate accountable-approval boundary remains in
  force.
- New challenges are told not to duplicate the authorization decision enforced
  by the accountable approval gate.

## Correct gate ordering and operator guidance

- `revise` and `needs-human-decision` challenge verdicts are evaluated before a
  missing approval artifact, so an approval error cannot hide an unresolved plan.
- Required human decisions are returned in the structured run result and escaped
  in terminal output instead of being reduced to a generic refusal.
- A run window requiring a real decision no longer recommends another identical
  run or a generic approval. An accepted frozen plan with only its accountable
  approval missing receives the exact operator-only `approve-planning` action.

## Safety boundary

Existing planning artifacts are not overwritten or automatically re-rolled.
`needs-human-decision` still blocks implementation until its answers are recorded
in the governing task or specification and a valid accepted challenge is produced.
The candidate is covered by focused adversarial regressions plus the planning,
approval, run-ready, and run-window test groups. Hosted Linux, Windows,
attribution, packaging, and protected-main checks remain required before release.
