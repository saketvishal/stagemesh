# StageMesh 0.6.3

StageMesh 0.6.3 is a compatible patch release. Publication is established only by the annotated `v0.6.3` tag, its non-prerelease
GitHub release, a successful trusted-publishing workflow, and the resulting immutable PyPI file; these notes alone are not publication.

## Guided project validation

- `stagemesh init` detects conventional project test commands without running them.
- An unconfigured Python project automatically receives the fixed first-task bootstrap gate; unknown non-Python stacks ask for the
  command the team already uses and show common examples.
- Non-interactive setup can use `--test-command "COMMAND"`; StageMesh writes a valid profile without requiring JSON knowledge.
- A suggested command is never run or persisted without confirmation. Only StageMesh's exact generated placeholder can be replaced;
  existing real profiles remain unchanged.
- A Python project without recognized test configuration receives a fixed bootstrap gate. Its first implementation can start, but completion
  requires at least one passing standard-library `unittest`; zero discovered tests fail closed.

## Guided coding-agent authorization

- Interactive setup lists detected coding agents, explains unattended project-edit permission, and authorizes all verified subscription
  agents with one confirmation; names or numbers remain available for an explicit custom selection.
- Codex and Claude login checks classify local subscription state without making a model call or exposing credentials.
- Non-interactive setup can repeat `--authorize-provider NAME`.
- Authorization remains explicit and project-local. Unknown providers are rejected, registration alone remains insufficient, and the
  independent-review policy still requires distinct eligible agents.

## Verification

The candidate includes synthetic acceptance for prompted and scripted setup, placeholder-only profile replacement, unknown-provider
rejection, JSON/non-interactive behavior, installed-wheel initialization, and the existing provider-authorization execution boundary.
