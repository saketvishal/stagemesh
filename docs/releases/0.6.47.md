# StageMesh 0.6.47

StageMesh 0.6.47 fixes the persisted-state gap left by 0.6.46. A verified
exact-candidate browser capture recorded after an earlier review reported
missing responsive evidence now authorizes one bounded re-review instead of
being stopped by the older unresolved finding before the reviewer can inspect
the capture.

## What changed

- StageMesh recognizes only a verified capture that post-dates every open
  browser-evidence finding on the same candidate.
- The bounded re-review prefers the reviewer that raised those findings, so a
  receipt-bound PASS can withdraw its own obsolete findings with a complete
  audit trail.
- Both PASS and FAIL_WITH_FINDINGS must bind the exact capture ID and every PNG
  hash. Provider failures and malformed answers do not consume the re-review;
  a terminal receipt does.
- The reviewer sees the persisted findings together with the verified PNGs and
  must report any issue that remains.
- Unrelated code findings, native-device evidence, owner decisions, older
  captures, changed PNGs, and wrong receipts do not gain this re-review path.

## Safety and compatibility

- The candidate, implementation worktree, and prior evidence are preserved.
  Implementation is not rerun to collect or review browser evidence.
- Provider selection remains dynamic and independent. The originating reviewer
  is a preference within the eligible pool, not a hard-coded provider.
- Existing findings are never silently deleted. They close only through the
  established attributable reviewer-withdrawal record.
- The capture remains headless, loopback-only, candidate-bound, and rehashed in
  the disposable review checkout.

## Acceptance coverage

The release includes a synthetic persisted-state regression matching the live
ordering: failed independent review, open browser and internal-acceptance
findings, a later verified exact-candidate capture, and a receipt-bound recheck.
Negative tests preserve unrelated code findings and reject terminal visual
verdicts without the exact receipt. Provider-pool coverage verifies that the
originating reviewer is preferred without removing eligible fallbacks.
