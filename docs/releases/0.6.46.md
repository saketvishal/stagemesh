# StageMesh 0.6.46

StageMesh 0.6.46 replaces the repeated browser-evidence approval loop with one
bounded, independently reviewed journey. An approved task that needs responsive
evidence no longer stops merely to ask the operator to approve StageMesh's own
verified technical captures.

## What changed

- A successful exact-candidate headless capture continues into independent
  review in the same bounded coordinator step. It no longer creates a
  `browser_evidence_decision_required` human-decision block.
- StageMesh copies verified PNGs into the disposable review checkout. The
  provider receives local bounded paths, routes, requested and measured CSS
  viewports, and SHA-256 hashes; it is not given browser control.
- A browser-evidence PASS must return the exact capture ID and every artifact
  hash. A plain PASS, wrong capture ID, missing hash, changed PNG, or inability
  to inspect the images is incomplete and cannot advance the task.
- If one reviewer returns an incomplete receipt, the bounded review retry can
  use another eligible independent reviewer. The implementer still cannot
  review its own candidate.
- Existing 0.6.45 `browser_evidence_decision_required` state is reclassified as
  recoverable work and resumes at independent review without rerunning
  implementation.
- `stagemesh evidence browser --task <id>` shows the current exact-candidate
  capture paths, measured viewports, hash prefixes, integrity, and review
  status. `diagnose`, `retry-task`, and run-window guidance now point to the
  automatic continuation path.

The optional `stagemesh evidence decide-browser` command remains available
when a governing specification explicitly calls for an accountable human
visual decision. It is not the default technical evidence gate.

## Safety boundaries

- Capture remains loopback-only, headless, bounded, and unavailable from a
  provider process.
- Review images live only in the disposable reviewer checkout and are rehashed
  after the provider returns.
- A newer capture invalidates an older receipt. Exact candidate and contract
  binding, workspace isolation, provider independence, and review audit traces
  remain required.

## Acceptance coverage

The release adds synthetic negative and journey tests for automatic recapture
through independent review, exact receipt acceptance, plain/wrong receipt
rejection, reviewer fallback, bundle mutation, local PNG delivery, legacy block
migration, CLI evidence visibility, and candidate advancement to integration.
